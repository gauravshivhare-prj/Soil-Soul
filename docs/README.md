# Documentation Index

This directory is the project’s source of truth for architecture and engineering practices.

| Document | Use it when |
|---|---|
| `architecture.md` | Understanding folder boundaries and module ownership |
| `setup-guide.md` | Installing, running, and verifying the applications |
| `coding-standards.md` | Writing or reviewing JavaScript |
| `code-documentation-standard.md` | Documenting functions, files, and complex logic |
| `api-conventions.md` | Adding or changing REST endpoints |
| `database-design.md` | Designing MongoDB collections and relationships |
| `security.md` | Handling authentication, authorization, secrets, uploads, and payments |
| `testing-strategy.md` | Choosing and running tests |
| `feature-workflow.md` | Implementing one feature safely |
| `deployment.md` | Preparing frontend and backend for deployment |
| `decisions.md` | Recording important architecture decisions |

## Keeping docs accurate

Update the relevant document in the same change that alters behavior, an API contract, data model, security rule, or setup procedure. Never document a command, test, or deployment as successful unless it was actually run and verified.
